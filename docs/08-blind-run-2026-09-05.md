## Silexara — what it exposed

**Over-extraction, 3.4×.** 259 claims against 76 expected. The rubric scores
§2 on precision *and* recall; we are paying heavily on precision. Gold treats a
claim as one atomic subject/predicate/value; we fragment the same content across
several claims.

**Recall ≈61%, and that is a crude lower bound.** 34 of 56 gold claims from
sources actually run matched at token overlap ≥0.30. The matcher is my own
jaccard over statement text, not the benchmark's scorer, and it demonstrably
under-counts: gold's *"primary current sensing modality is geophone-based
vibration; magnetic and electric-field…"* is present in our output as *"the
primary sensing layer is vibration-based (geophones); magnetic and
electric-field sensing will be added later"* and scores as a miss. Treat 61% as
a floor, not a measurement.

**My run coverage was incomplete — a setup error, not an extractor result.**
The glob missed SRC-08 (`.txt`), SRC-11 (`.eml`) and SRC-18 (`.html`), and SRC-01
and SRC-07 are PDFs needing the GPU pod, which was stopped. 20 of 76 gold claims
come from sources never processed. Rerun with full coverage before quoting any
recall number.

## Defect in the answer key

**57 of 76 gold claims carry the anonymiser corruption**, the same bug already
found in the corpus (`MAContinental Grid OperatorN`). The substitution replaces
the literal substring `rte`, so:

- `asserted` → `asseContinental Grid Operatord` (51 records)
- `reported` → `repoContinental Grid Operatord` (2)
- `reported_hearsay` → `repoContinental Grid Operatord_hearsay` (1)

`epistemic_class` is therefore unusable for scoring as shipped, and
`SCORING_RUBRIC.md` is affected too ("*state inveContinental Grid Operatord*").
Worth reporting upstream before anyone scores against this key.

## Two model mismatches, neither an extraction failure

**Different claim shape.** Gold is `subject` / `predicate` / `value`
("Silexara" / `product_architecture` / "sensing + AI + response"). We emit
`entity` / `metric` / `measurement` / `value`. Any real scoring needs a mapping
between the two; token overlap is a stopgap.

**Different epistemic vocabulary.** Gold uses `source_assertion`,
`stated_position`, `analyst_research`, `analyst_assessment`, `decision_frame`,
`decision_status`. We use the five-class enum. These are not the same axis, and
the dictionary's §3 migration is what would reconcile them.

**Most of the rubric is out of scope for this layer.** Categories 1, 5, 6, 7 and
8 — provenance formation, bitemporal versioning, discrepancy handling, position
and authority separation, bounded propagation — are vault and dynamics
capabilities, not L2 extraction. A rubric total would mostly measure components
this run does not exercise.

## What to do next

1. Rerun with full source coverage (fix the glob; restart the pod for the two
   PDFs) before treating any recall figure as real.
2. Report the anonymiser corruption upstream; ask for a clean key.
3. Attack precision, not recall. 3.4× over-extraction is the clearer defect, and
   unlike recall it is visible without a working answer key: compare our claim
   count per source against gold's atomicity and find where we fragment.
4. Build a proper cross-schema matcher (subject/predicate/value ↔
   entity/metric/measurement) before quoting precision or recall as a number.
