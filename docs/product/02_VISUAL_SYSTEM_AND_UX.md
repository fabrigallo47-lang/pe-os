# PANTA Visual System + UX Rules

## Core principle
**Consistency lives in the shell and primitives. Identity lives in the interaction.**

Do not make every room a three-column graphite layout.

## Shared language
- dark graphite/mineral operating environment;
- warm off-white human-facing text;
- restrained accent used for actual selection/action/state;
- institutional sans for human prose;
- mono only for genuine metadata such as dates, counts, IDs where useful;
- hairlines/alignment/spacing before boxes;
- no soft shadows;
- no generic rounded SaaS card system;
- no traffic-light dots as the primary status language;
- no decorative connector lines.

## Material hierarchy
Different jobs may use different materials:
- evidence = dense, inspectable;
- reading/judgment = calm, open;
- consequences = compact;
- artifact writing = document-like;
- model = grid-like;
- temporal replay = time-dominant.

## Rhythm
Do not distribute whitespace evenly.
Use compression where work happens and breathing room where judgment happens.
Avoid giant fixed-height empty containers.

## Typography
The interface should look authored, not generated.
Avoid:
- giant landing-page headlines inside working tools;
- eight labels explaining obvious regions;
- awkward wrapping/truncation;
- excessive uppercase mono copy.

## PANTA craft signature
A provenance/relationship rule may appear only when it encodes a real relationship. If a line exists, it means something.

## Investor-language rule
Prefer:
- What supports this
- Still missing
- Where this matters
- What changed
- Test without this

Avoid exposing schema/engine terms.

## Visual review bar
A screen is not excellent merely because it is consistent.
It must bend to the investor's mental model and make the primary cognitive act obvious within seconds.
